# Releasing

Releases are built by `.github/workflows/release.yml`, generated by
[dist](https://github.com/axodotdev/cargo-dist) from `dist-workspace.toml`. Pushing a tag like
`v0.2.0` builds the Linux and macOS archives, the shell installer, checksums and build
attestations, and publishes them as a GitHub Release with the matching `CHANGELOG.md` section as
release notes.

1. In a PR: bump `version` in `Cargo.toml` (and run `cargo check` to update `Cargo.lock`), and
   add a `## <version>` section to `CHANGELOG.md`. Merge once CI is green.
2. Tag the merge commit on `main` and push the tag:

   ```sh
   git switch main && git pull
   git tag v0.2.0
   git push origin v0.2.0
   ```

3. Watch the Release workflow (`gh run watch`), then check the release page and the installer:

   ```sh
   curl --proto '=https' --tlsv1.2 -LsSf https://github.com/dtrotzky/neet-tui/releases/latest/download/neet-installer.sh | sh
   neet --version
   ```

Changing the release setup (targets, installers, pinned actions): edit `dist-workspace.toml` and
run `dist generate` (`cargo install cargo-dist --locked`) instead of editing the workflow by
hand; the release workflow checks that the two match. When Dependabot bumps an action in
`release.yml`, update the matching commit in `[dist.github-action-commits]` too.
